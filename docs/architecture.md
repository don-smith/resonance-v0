# Architecture

Resonance is a local, manifest-driven workspace. The CLI reads the current working directory as the authoritative repository root, offers `resonate install` when `.resonance/config.json` is absent, and starts a localhost HTTP server only after a configuration exists. Installation always writes Shell and interactively selects Home, Documentation, Architecture, Backlog, and Doctor; selecting Architecture or Backlog also creates minimal missing repository artifacts without overwriting existing files. The configured package entries are an authoritative allowlist. The server serves the Shell document and package assets, then dispatches package-owned API routes under `/api/<package-id>/...`. `resonate member init` bootstraps a self-contained member-package repository with an explicit manifest, local contract snapshot, and package-authoring skill; `resonate member package create` scaffolds packages inside that repository.

Packages are Resonance's general extensibility and implementation units. A workspace is a user-visible surface listed in the workspace navigation and mounted by Shell. A package may provide a workspace, but not every package must be a workspace; Shell is a required infrastructure package, and Home is the repository landing page opened from Shell's repository title. Neither is a workspace. Current Documentation, Architecture, Backlog, and Doctor packages provide workspaces. External member packages may provide additional workspaces. This relationship is descriptive for now and does not add workspace metadata or a second configuration model.

## Package boundaries

- [**Shell**](../src/packages/shell/README.md) owns the fixed browser bootstrap, primary navigation, repository-title Home activation, workspace mounts, activation rollback, and shared layout.
- [**Home**](../src/packages/home/README.md) reads the configured repository landing source and renders the landing page in the browser without contributing workspace navigation.
- [**Documentation**](../src/packages/documentation/README.md) discovers Markdown beneath `HostContext.repositoryRoot`, exposes the tree/document and bounded agent routes, renders the Documentation workspace whenever Documentation is activated, navigates relative links between discovered documents, and applies agent-requested Markdown edits.
- [**Architecture**](../src/packages/architecture/README.md) reads the committed `architecture/` model and projections, exposes bounded evidence and deterministic validation, and renders the architecture workspace when explicitly configured. Its validation contract is documented in [Architecture verification](architecture-verification.md).
- [**Doctor**](../src/packages/doctor/README.md) discovers and runs explicit target-repository checks, including Bun unit and integration tests, TypeScript type checking, repository-owned lint/format commands, and read-only Bun dependency checks, while persisting only bounded latest results.

Packages contribute method-aware routes, assets, navigation metadata, one browser module, and optional package-owned Tasks through the shared package contract. Resonance Actions evaluates those Tasks dynamically and owns only the generic session, preview/confirmation transport, and browser surface; skills, operations, evidence, validation, writes, and dismissal semantics remain inside the contributing package. Team packages are selected by checked-in `.resonance/config.json`; member packages are selected by ignored `.resonance/member-config.json` and loaded from one external live checkout. Team packages load first and win contribution conflicts. The host validates contributions transactionally, keys routes by `METHOD pathname`, and keeps optional package failures isolated. Route handlers receive package-safe request/response capabilities: bounded JSON parsing, JSON responses, request-abort notifications, SSE streams, and one bounded package-scoped JSON state document. They do not receive Node HTTP objects or arbitrary filesystem access. Package-owned agent runtimes are explicit exceptions: the Backlog agent mounts the viewed repository read-only for listing, reading, glob, and grep while keeping canonical Backlog mutations behind domain tools; the Architecture agent provides the same repository inspection capabilities and may additionally write or edit files in the configured architecture artifact root and Markdown documents; the Documentation agent receives the active Markdown document and optional highlighted text and may edit configured Markdown documents through bounded package tools. Credentials remain unavailable, and shell execution, traversal, and symlink escapes are rejected. Package cleanup callbacks run in reverse registration order when the HTTP server closes; disposal is idempotent.

## Transport and safety boundaries

The shared HTTP layer bounds JSON request bodies and provides SSE framing. The server preserves `405` responses and lists registered methods in `Allow`. SSE handlers do not attempt a JSON response after headers are committed.

Filesystem access remains server-owned. Resonance remains localhost-only.

Browser preferences are package-owned, not shared workspace state. Documentation, Backlog, Architecture, and Doctor each use a distinct local-storage namespace for their own agent-panel visibility and navigation state; tree packages also own their collapsed nodes and selected item. A package reads that state when activated and writes each change immediately, while invalid or unavailable storage falls back to the normal defaults.

Resonance-owned telemetry is host infrastructure rather than a configured package. The host creates one process-level telemetry interface and passes it through `HostContext`; packages emit structured logs and spans without depending on an exporter. Each record carries the viewed repository's Git origin name (or directory name when no origin is available) as `repository`, and Langfuse also receives it as a resource attribute so one local instance can distinguish repositories. The telemetry interface also supports grouping related traces with `session(sessionId)`; the Langfuse adapter maps that exporter-neutral session identity to `langfuse.session.id`. Console telemetry is enabled by default, while Langfuse export is optional repository-local process configuration loaded from the viewed repository's gitignored `.resonance/.env`. Agent turn and model stream observations provide structured request/response fields; the host exports their content only when `RESONANCE_TELEMETRY_CAPTURE_CONTENT=true`, while secret-looking fields and values remain redacted. Exporter failures do not fail package requests.

Architecture artifacts are repository-authored LikeC4 `.c4` files under the top-level `architecture/` directory, with package-owned JSON metadata for rules, patterns, and decisions. LikeC4 parses and layouts the model; `@likec4/diagram` renders the browser views. The Architecture package treats implementation evidence as authoritative for what exists, authored assertions as authoritative for intended structure, and views as projections. Validation is deterministic, compares only claims for which code has positive evidence, and reports `pass`, `fail`, or `unknown`; it does not block startup. Its canonical-model gate and six authored checks, including their source-binding and coverage semantics, are documented in [Architecture verification](architecture-verification.md). Its optional agent uses the configured local OpenAI/OpenRouter model through package-owned tools and a repository-wide filesystem backend that allows architecture-artifact and Markdown updates while excluding credential files and implementation writes.
